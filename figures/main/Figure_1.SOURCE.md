### The Arial revision in detail

The author authorised changing the typeface from DejaVu Sans to Arial so that Figure 1 matches
Figures 2–7, which `src/viz/style.py` sets to Arial. **Nothing else changed.** The two edits to the
approved source were the font family and the replacement of a hard-coded absolute home directory by
paths derived from the script's own location. Layout, wording, colours, white box backgrounds, black
text, font weights (only the panel letters **A** and **B** are bold; "Train and evaluate", "TCR
residues" and "MHC residues" stay regular), the STCRDab cylinder with its two internal curved
dividers and the label above it, the molecular illustration, both contact maps, every connector and
the horizontal Q/K/V/σ key at the bottom are the approved ones. No dataset count and no input or
output dimension appears in the artwork. Arial is narrower than DejaVu Sans at the same point size,
so nothing collided and **no spacing was adjusted**.

Arial is resolved explicitly rather than requested by name: matplotlib's sans-serif list would fall
back to DejaVu Sans with only a warning if Arial were absent, so the script calls
`font_manager.findfont(..., fallback_to_default=False)` for the regular and bold faces, asserts the
resolved files are Arial and not DejaVu, and asserts that Arial's own `cmap` contains σ, α, β, Å, ×,
the en dash and the middle dot, so no glyph falls through to another font. It resolved
`/usr/share/fonts/truetype/msttcorefonts/Arial.ttf` and `Arial_Bold.ttf` (the msttcorefonts
package). The exported PDF embeds `ArialMT` and `Arial-BoldMT` as subset CID TrueType, with **no
Type 3 font and no DejaVu**; the SVG references `font-family: 'Arial', sans-serif` and keeps text
editable (`svg.fonttype: none`).

The installed files were rendered in the project environment `dl_env` (Python 3.10.18, matplotlib
3.10.8). Matplotlib's raster output is not byte-stable across its own versions, so a different
matplotlib will produce a visually identical figure with a different SHA-256 and the builder will
then refuse to build. Re-render in `dl_env` rather than updating `FIG1_SHA256`.

Fonts across the whole figure set were audited with `pdffonts`: all seven main figures and all nine
supporting figures embed Arial only. **No mathematical-symbol font exception is required**, no
figure uses matplotlib mathtext, so every symbol, including σ and the minus sign, is a literal
Unicode character drawn from Arial. The manuscript body font is unchanged (Times New Roman).

## Scientific content, as verified against the repository

* Molecular panel: `data/structures/stcrdab/imgt/1ao7.pdb`. Chain assignment matches the STCRDab
  header (`ACHAIN=D BCHAIN=E MHCCHAINS=AB AGCHAIN=C`), so TCRα blue = chain D, TCRβ purple = chain E,
  MHC green = chain A, peptide magenta = chain C. β2-microglobulin and the α3 domain are outside the
  view and are omitted.
* Both contact maps are 1AO7, read from the frozen `results/tables/pairmaps_tcr70_p84v2.npz`:
  panel A shows the crystal labels `Y[1ao7]` (31 contacts over 5,208 resolved pairs) and panel B the
  stored out-of-fold prediction `pred_model[1ao7]`, with `S[1ao7] == 0` masked grey in both. Neither
  map is drawn by hand.
* The architecture drawn in panel B is `PairNet` in `scripts/19_train_pairmap.py`, which
  `scripts/24_run_all.py` instantiates with `mhc_len = 84` to produce the p84v2 pairwise results:
  residue + segment + position embeddings on the TCR side, residue + position embeddings on the MHC
  side, two Transformer encoder layers for the TCR and one for the MHC, cross-attention with the TCR
  as queries and the MHC as keys and values, a residual connection and layer normalisation, then a
  bilinear head (`wt`, `wm`) with a learned pair-position term, a scale and a bias, and a sigmoid.
* The figure carries no performance value, no dataset count and no claim that the per-residue
  variant used for the primary comparison shares this architecture.

## Overwrite protection: do not disable

1. `build_manuscript_docx_v3.js` hashes `figures/main/Figure_1.png` on every build and **throws**
   unless it is the approved file, naming the expected and found hashes and where to restore from.
   It also asserts the PNG is 6480 × 4230.
2. `scripts/70_fig1_workflow.py`, which produced the superseded script-drawn figure, is kept for the
   audit trail but refuses to run without `--allow-superseded` and writes only to
   `figures/previous_versions/`. It can no longer reach `figures/main/`.
3. `figures/FIGURE_MANIFEST.md`, `docs/manuscript/BUILD_NOTES_v4.md`, the project notes and `HANDOFF_1.md`
   all record which file the builder uses and that it is not regenerated.

`FIG1_SHA256` in the builder is updated only when the author approves a new figure. It was updated
on 2 November 2026 for this font-only revision; the previous value `a447b2a8…b45bbd0` belongs to the
DejaVu Sans version now preserved as
`figures/previous_versions/fig1_approved_dejavu_20261102.{png,pdf,svg}`.
